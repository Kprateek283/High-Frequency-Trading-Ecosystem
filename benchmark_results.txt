#         4        4      1675517   1601272  ( -4%, spread 53% -> 37%)
#
# Cause is structural, not a bug. The exchange runs 11 threads that request
# realtime; EXCHANGE_CPUSET=0-7 is 8 logical CPUs; isolcpus is not configured.
# Under SCHED_OTHER, CFS timeslices 11 runnable threads across 8 CPUs. Under
# SCHED_FIFO at equal priority a thread is never preempted by a same-priority
# peer -- it runs until it blocks or the RT throttle fires -- and the engine
# never blocks (engine.cpp spins on __builtin_ia32_pause). Four shards therefore
# hold four CPUs indefinitely while the other seven RT threads fight over what is
# left. kernel.sched_rt_runtime_us=950000 then adds a ~50 ms deschedule per
# second on top of that.
#
# SCHED_FIFO only pays off once the RT threads have cores to themselves:
# isolcpus for the hot path, threads <= isolated CPUs, and a decision on
# sched_rt_runtime_us. Until then, benchmark with RT_PRIORITY=0.
# See docs/benchmark-setup.md section 1.
#
# An earlier RT run also showed that PARTIAL realtime is worse than none: with
# GATEWAY_CORES unset the gateway workers returned before requesting RT, so the
# spinning engine shards ran at priority 80 while their producers stayed at
# SCHED_OTHER on the same cpuset. That inversion cost 4x1 ingest 533k -> 264k at
# 96% spread. Fixed -- affinity and scheduling policy are now independent.
#
# Note on the governor: `tuned` is active and this laptop was on battery, so it
# reverted scaling_governor to powersave between being set to performance and
# the sweep running. Both sweeps compared above are powersave, so the comparison
# holds, but a performance-governor run needs tuned disabled or AC power.
